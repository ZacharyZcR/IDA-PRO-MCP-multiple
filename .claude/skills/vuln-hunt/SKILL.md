对当前 session 的二进制文件进行漏洞模式扫描。此功能仅用于合法授权的安全研究和 CTF 竞赛。

## 执行步骤

### 阶段 1: 危险函数定位

1. 调用 `imports` 获取导入表
2. 用 `search` 或 `find_insns` 搜索以下危险函数的调用：

**内存操作（高危）:**
- `strcpy`, `strcat`, `sprintf`, `vsprintf` — 无长度限制
- `gets` — 经典缓冲区溢出
- `memcpy`, `memmove` — 长度参数可控时危险

**格式化字符串:**
- `printf`, `fprintf`, `syslog` — 用户输入直接作为格式化字符串

**整数相关:**
- `malloc`, `calloc`, `realloc` — 参数可能整数溢出
- `read`, `recv` — 长度参数

**命令注入:**
- `system`, `popen`, `exec*`, `ShellExecute`, `WinExec`, `CreateProcess`

3. 对每个找到的危险调用，用 `xrefs_to` 定位所有调用点

### 阶段 2: 上下文分析

4. 对每个调用点，调用 `decompile` 获取所在函数的伪代码
5. 分析参数来源：
   - 参数是否来自用户输入（stdin, recv, read, argv, 环境变量）
   - 是否经过长度/边界检查
   - 是否存在 sanitize/validate 逻辑
6. 调用 `callers` 追溯调用链，确认数据流

### 阶段 3: 模式匹配

7. 用 `find_insns` 搜索以下指令模式：

**栈溢出:**
- `sub rsp, X` 后跟无边界检查的 `rep movsb/movsd`
- 局部数组 + 循环写入无长度限制

**堆漏洞:**
- `malloc` → 使用 → `free` → 再次使用（UAF）
- `free` 后未置 NULL
- Double free 模式

**整数溢出:**
- 乘法/加法后直接用于 `malloc` 参数
- 有符号/无符号比较混用

8. 调用 `stack_vars` 分析栈变量布局，寻找：
   - 缓冲区相邻于函数指针
   - 缓冲区相邻于长度变量

### 阶段 4: 特定漏洞类型

如果用户指定了函数（$ARGUMENTS），聚焦分析该函数：

9. 调用 `decompile` + `basic_blocks` 获取完整控制流
10. 调用 `stack_frame` + `stack_vars` 获取栈布局
11. 逐路径分析是否有未检查的边界条件

```
|------|---------|---------|
| strcpy | N | 高 |
| ... | ... | ... |

### 发现的潜在漏洞

#### [编号] [漏洞类型] @ 0x[地址]
- **位置**: [函数名] + 0x[偏移]
- **类型**: 缓冲区溢出 / 格式化字符串 / 整数溢出 / UAF / 命令注入
- **风险**: 高/中/低
- **描述**: [详细说明]
- **伪代码**: [相关代码片段]
- **利用条件**: [是否可从外部触发，数据流路径]

### 汇总
- 高风险: N 个
- 中风险: N 个
- 低风险: N 个
- 建议优先处理: [编号列表]
```

## 注意事项

- 此技能仅用于合法授权的安全研究、渗透测试和 CTF
- 误报率较高，每个发现都需要人工确认
- 不覆盖逻辑漏洞、密码学弱点等需要深入理解的漏洞类型
