对当前 session 的二进制文件执行完整的脱壳流程。

## 执行步骤

### 阶段 1: 壳识别

1. 调用 `detect_packer` 获取壳类型
2. 调用 `detect_entropy` 获取熵值分析
3. 如果 `is_packed == false` 且熵值正常，告知用户文件未加壳，流程结束

### 阶段 2: 脱壳

4. 调用 `auto_unpack` 执行自动脱壳
5. 如果失败，尝试 `unpack_generic` 作为备选
6. 如果全部失败，输出已知信息并建议手动脱壳方案

### 阶段 3: 验证

7. 脱壳成功后，对输出文件再次运行 diec 验证（通过 Bash 调用 `diec --json [unpacked_file]`）：
   - 确认壳已被移除
   - 检查编译器/链接器信息是否可见
   - 检查熵值是否降低到正常范围
8. 对比脱壳前后的文件大小

### 阶段 4: 载入分析

9. 将脱壳后的文件路径告知用户
10. 建议用户将脱壳文件放入 `analyze/` 目录并创建新 session 进行深度分析

## 输出格式

```
## 脱壳报告: [文件名]

### 壳识别
- 检测到: [壳名称] [版本]
- 类型: [Packer/Protector/Cryptor]
- 脱壳前熵值: [数值]

### 脱壳结果
- 状态: [成功/失败]
- 使用方法: [upx / unipacker / 手动]
- 脱壳前大小: ... → 脱壳后大小: ...

### 验证
- diec 复检: [无壳残留 / 仍有壳特征]
- 脱壳后熵值: [数值]
- 编译器识别: [可见/不可见]

### 输出文件
- 路径: [脱壳后文件路径]

### 下一步
- 建议: /deep-analyze 进行深度逆向分析
```

## 注意事项

- 脱壳过程保留原始文件不修改，脱壳结果保存到 `unpacked/` 子目录
- unipacker 仅支持 PE32（32 位 Windows 可执行文件）
- 对于 VMProtect/Themida 等虚拟化壳，自动脱壳大概率失败，需要手动处理
