对比两个 session 中的二进制文件，识别差异。用于补丁分析、版本比较、加壳前后对比等场景。

需要两个参数：$ARGUMENTS[0] = session_id_1, $ARGUMENTS[1] = session_id_2

## 执行步骤

### 阶段 1: 信息采集

对两个 session 分别采集信息（通过切换 session）：

1. 切换到 session_1：
   - `idb_meta` — 基本信息
   - `list_funcs` (count=500) — 函数列表
   - `imports` — 导入表
   - `strings` (count=200) — 字符串
   - `segments` — 段信息
   - `entrypoints` — 入口点

2. 切换到 session_2，执行同样的采集

### 阶段 2: 差异分析

3. **函数对比**:
   - 新增的函数（session_2 有但 session_1 没有）
   - 删除的函数
   - 名称相同但大小不同的函数（可能被修改）
   - 对大小变化的函数，分别 `decompile` 对比伪代码

4. **导入表对比**:
   - 新增的导入
   - 删除的导入
   - 关注安全相关 API 的增减

5. **字符串对比**:
   - 新增的字符串
   - 删除的字符串
   - 关注可疑字符串的变化

6. **段信息对比**:
   - 大小变化
   - 权限变化
   - 新增/删除的段

### 阶段 3: 深入对比

7. 对变化的函数逐个 `decompile`，标记具体差异
8. 分析差异的安全影响

## 使用示例

```
/binary-diff af85e830 1b6843e3
```

对比 session af85e830 和 1b6843e3 中的二进制文件。

## 注意事项

- 函数量大时仅对比前 500 个函数
- 伪代码对比基于文本相似度，可能存在误差
- 如果两个文件架构不同（如 x86 vs x64），对比意义有限
