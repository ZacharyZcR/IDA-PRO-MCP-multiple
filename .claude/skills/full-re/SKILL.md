对当前 session 的二进制文件执行完整的逆向工程分析流程。

这是一个端到端的自动化流程，按顺序串联所有分析阶段。

## 执行流程

### Phase 1: 快速分类

1. 并行调用：
   - `idb_meta` — 文件元数据
   - `detect_packer` — 壳识别
   - `detect_entropy` — 熵值分析
   - `segments` — 段信息
   - `entrypoints` — 入口点
   - `imports` — 导入表
   - `strings` (count=100) — 字符串采样

2. 输出简短分类摘要，决定后续路径

### Phase 2: 脱壳（如需要）

3. 如果 `detect_packer` 返回 `is_packed == true`：
   - 调用 `auto_unpack` 自动脱壳
   - 验证脱壳结果
   - 告知用户脱壳后文件路径，建议创建新 session 继续分析
   - **如果脱壳失败**：记录失败原因，继续对加壳文件做尽可能的分析

4. 如果未加壳，直接进入 Phase 3

### Phase 3: 结构分析

5. 调用 `list_funcs` (count=200) 获取函数列表
6. 筛选高价值函数：
   - 有意义的名称（非 `sub_`）
   - 入口函数（main, _start, WinMain, DllMain）
   - 大函数（指令数多的）
7. 调用 `callgraph` 从入口点生成调用图

### Phase 4: 核心逻辑逆向

8. 从入口点开始，调用 `decompile` 反编译
9. 对入口点调用的函数递归反编译（最多展开 3 层）
10. 对每个函数分析：
    - 功能是什么
    - 输入参数含义
    - 返回值含义
    - 调用了哪些关键 API

### Phase 5: 数据与字符串分析

11. 调用 `analyze_strings` 查找有价值的字符串
12. 对关键字符串调用 `xrefs_to` 找到使用位置
13. 调用 `list_globals` 查找全局变量

### Phase 6: 安全评估

14. 检查导入表中的高风险 API：
    - 内存操作: VirtualAlloc, WriteProcessMemory
    - 进程操作: CreateProcess, CreateRemoteThread
    - 网络通信: socket, connect, send, recv
    - 文件操作: CreateFile, DeleteFile
    - 注册表: RegSetValue, RegCreateKey
15. 对高风险 API 的调用点做上下文分析

## 注意事项

- 整个流程可能耗时较长，保持耐心
- 遇到混淆严重的代码，标记但不深入
- 优先分析有语义信息的部分
- 如果文件较大（>10MB），缩减分析范围，聚焦入口和关键函数
